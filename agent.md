# Инструкция для продолжения проекта «Монополия»

Обновлено 8 октября 2026. С этого момента работу ведут параллельные агенты под координацией прораба — распределение блоков и правила в FOREMAN_PLAN.md. Этот файл — передача контекста для Claude и других агентов. Подробная история блоков находится в PROJECT_MEMORY.md, библиотека — в UI_KIT.md.

## Задача и ограничения пользователя

- Собственная верстка по Figma: главная и две внутренние продающие страницы. Цель — заявка через форму. Приоритет — скорость загрузки.
- Все три страницы сверстаны и сверены на desktop 1440. Адаптив разрешён текущими задачами; desktop ≥1200 сохранять. Владение компонентами и диапазоны — в FOREMAN_PLAN.md и design-reference/tasks/_common.md.
- Фон каждой секции тянется на всю ширину окна. Контент обычно 1160 px, центрирован; исходный desktop макет 1440 px.
- Шапка — один общий компонент для всех страниц, фиксирована сверху при скролле. Существующие hover и меню сохранить.
- Не пушить без разрешения. Не публиковать и не подключать реальные отправки заявок самовольно.
- Пользователь продолжает словами «дальше» / «продолжай»: это означает сверстать следующий блок по порядку макета, проверить и показать результат.
- Сохранять уже сделанную верстку и общие компоненты. Не начинать с нуля.

- Адаптив главной сделан (9 окт, R1: планшет ≤1199, телефон ≤767, design-reference/responsive-home-plan.md, src/styles/home-responsive.css); /sell/ и /buy/ адаптируют свои владельцы.

## Стек и расположение кода

Astro + TypeScript + обычный CSS, статическая сборка. Без React/Tailwind и лишних библиотек.

- src/pages/index.astro — главная, последовательность секций.
- src/pages/ui-kit.astro — библиотека элементов (проверить точный файл через список src/pages при необходимости).
- src/components/ — общие элементы и отдельные компоненты секций.
- src/styles/tokens.css — цвета, шрифты, размеры, интервалы и прочие токены.
- src/styles/global.css — общие стили элементов; отдельные CSS секций находятся рядом в src/styles.
- src/layouts/SiteLayout.astro — общий каркас и шапка.
- public/assets/ — локальные SVG, WebP и другие ресурсы, имена соответствуют экспорту Figma.
- design-reference/original-assets/ — исходные растровые экспорты до оптимизации.
- PROJECT_MEMORY.md — решения, описание реализованных блоков и проверок.

Шрифты локальные: Forma для заголовков, Calibri для текста, Denistina для рукописных вставок. Использовать существующие токены и подключения.

## Как верстать

1. Прочитать текущую последовательность index.astro и PROJECT_MEMORY.md, определить следующий блок.
2. Получить его контекст и скриншот Figma. Проверить текст, размеры, относительные координаты, слои, повороты, обрезку изображений.
3. Найти подходящие существующие компоненты: Paper, Button, StaffCard, Carousel, SpeechBubble, PartnerLogos и другие. Переиспользовать или расширять параметрами, сохраняя прежние вызовы и UI kit.
4. Сделать отдельный компонент секции и его CSS, подключить в index.astro в правильном порядке.
5. Использовать обычный layout (grid/flex) для текста и карточек. Абсолютные позиции применять для декоративных слоев, портретов, SVG-теней, лент, рваных краев — там, где они заданы макетом.
6. Сохранять все статические ресурсы из Figma локально. Временные MCP URLs в коде не оставлять. Загружать по инструкции ответа MCP; в прошлых ответах явно разрешалось скачивание предоставленных URL.
7. Растровые исходники сохранять в design-reference/original-assets, оптимизировать в WebP (использовался sharp, quality 88) и отдавать из public/assets. Для первого экрана отдельно учитывать скорость; нижние картинки loading=lazy.
8. SVG-тени людей — самостоятельные исходные векторы из Figma. Не заменять CSS drop-shadow. Не перерисовывать и не подменять экспорт. Не переопределять root width/height SVG произвольным растягиванием.
9. Проверять зеркальность, порядок слоев, размеры и crop портретов: у некоторых фото исходный размер сильно больше видимого контейнера, это намеренно.
10. Не использовать скриншот дизайна как картинку всей секции. Макет собирается настоящим HTML/CSS и отдельными ресурсами.
11. Если в Figma нет файла, видео, ссылки или дополнительных карточек — не придумывать контент. Делать честную заглушку и отмечать ограничение.

## Проверка результата

- Форматировать только измененные файлы: npx prettier --write <файлы>.
- npm run check — Astro/TS диагностика.
- npm run build — статическая сборка.
- npm run dev — локальная страница http://127.0.0.1:4321/.
- Проверить блок в браузере на 1440 px, сверить с Figma. Одного build недостаточно.
- Проверить загрузку каждого видимого изображения (complete && naturalWidth > 0), размеры, слои и взаимодействие.
- Сохранить снимок результата в корне проекта, например home-telegram-desktop.png, и показать пользователю.
- В текущем browser automation предпочтителен обычный viewport screenshot. clip/fullPage ранее давали ложное визуальное обрезание при больших портретах; проверять реальный вид окна, а не исправлять верстку по такому артефакту.
- Временный viewport override сбрасывать после проверки.
- Записывать завершенный блок, источники и ограничения в PROJECT_MEMORY.md.
