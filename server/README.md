# Сервер каталога и заявок

Node 22+, без npm-зависимостей. Сайт — статический GitHub Pages; сервер — VPS.

## Локально и добавление карточки

```sh
npm run dev:all
```

Откройте http://127.0.0.1:4321/ или http://127.0.0.1:4321/admin/. Команда ведёт
сайт и API в одном терминале; `Ctrl+C` останавливает оба. В браузере API всегда
доступен через этот же origin.

> Продакшен: на VPS сайт и API живут на одном домене за nginx: `/api/*`, `/lead`
> и `/media/*` идут в Node, остальное — статика. Готовый маршрут —
> [nginx.conf.example](nginx.conf.example).

В админке → вход → «Добавить объект» → поля и фото → «Сохранить».
«Сохранено — карточка уже на сайте» означает обновлённый API. Посетители получают
изменение после открытия страницы и приближения к карусели; публичный кэш — 60 с.
Текущая вкладка посетителя обновляется один раз. Скрытые/удалённые записи исчезают
при следующем открытии страницы. При недоступном API остаются вшитые карточки;
успешный пустой ответ очищает карусель.

## Доступ в админку

Вход только по логину и паролю. Смена пароля: `node server/admin-set-password.mjs`,
затем перезапуск Node. Команда сохраняет хэш пароля в `.env` с правами 600.
Telegram для входа в админку не используется.

## Переменные окружения

Образец — `.env.example`; `.env` не входит в сборку, образ или репозиторий.

- `ADMIN_USER`, `ADMIN_PASSWORD_HASH` — один аккаунт, проверка scrypt.
- `DATA_DIR` — отдельный writable каталог. По умолчанию `.local-admin/` в корне проекта.
  При первом запуске копируется `src/data/properties.json`; исходник сайта не изменяется.
- `ADMIN_API_ORIGIN` — точный публичный HTTPS origin Node/nginx; в dev обычно не нужен.
- `ALLOWED_ORIGINS` — точные origins сайта через запятую, без `*`; локально 127.0.0.1:4321.
  Для стабильного Serveo: `ALLOWED_ORIGINS=https://monopolia.serveousercontent.com,http://127.0.0.1:4321`.
  При `TRUST_PROXY=1` на loopback за share ручной список для туннеля не требуется:
  вход и заявки принимают Origin, совпадающий с проверенными forwarded-заголовками.
  Запуск Serveo и ограничения — [README](../README.md#serveo-бесплатная-стабильная-ссылка).
- `PUBLIC_CATALOG_ENDPOINT` — URL `/api/catalog`, `PUBLIC_MEDIA_BASE` — origin фото.
  Публичные настройки задаются при сборке Astro; в dev без них используются относительные
  `/api/catalog` и `/media/...` через прокси 4321.
  Production без них сохраняет вшитые карточки; для онлайн-редактирования они обязательны.
- `PORT=8787`, `HOST=127.0.0.1`. `TRUST_PROXY=1` — только Node на loopback за своим nginx
  или `npm run share`. Для админки share передаёт `X-Forwarded-For` туннеля; API читает
  первый корректный IP только от loopback, чтобы лимит входа был отдельным для клиентов.
  Share сохраняет Origin браузера и передаёт публичные `X-Forwarded-Host` / `X-Forwarded-Proto`.
  При `TRUST_PROXY=1` админка и `/lead` дополнительно принимают точное совпадение Origin
  с `proto://host` только от loopback-сокета; хост строго проверяется, белый список сохраняется.
  **Включать только когда API слушает loopback за доверенным прокси**, проверяющим и
  перезаписывающим эти заголовки. Без TRUST_PROXY forwarded-заголовки игнорируются.
- `ADMIN_API_PORT` — порт Node для dev-прокси всех `/api/*`, `/lead` и `/media/*`,
  по умолчанию 8787.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — доставка заявок существующим `/lead`.
- `PUBLIC_LEAD_ENDPOINT` — публичный HTTPS URL `/lead`, задаётся при сборке сайта.
- `PUBLIC_SITE_ORIGIN` — origin сайта, может быть резервом для `ALLOWED_ORIGINS`.
- `TELEGRAM_API_BASE` — доверенный HTTPS Telegram-прокси при необходимости.
- `LEAD_DRY_RUN=1` — заявки без доставки.

## Хранение и API

В `DATA_DIR`: `properties.json`, одна `properties.json.bak`, `media/`.
Одна Node-инстанция с одним DATA_DIR.
Запись каталога: очередь → проверка revision (409) → копия предыдущего → tmp/fsync/rename.
Фотографии неизменяемые; старые и неиспользованные файлы остаются для отката,
очистка диска вручную. `.bak` хранит только предыдущий каталог; внешняя копия — отдельно.

Публичные GET `/api/catalog` (visible, без id/visible, ETag, max-age=60) и
`/media/<случайное имя>.webp` (immutable, год). Админка: session GET/POST/DELETE,
catalog GET/PUT, media POST octet-stream до 1,5 МБ.
Canvas в браузере делает 4:3 и 360/680 WebP; сервер проверяет RIFF, размеры,
отсутствие анимации/метаданных. Оригиналы и EXIF не сохраняются.

## VPS и HTTPS

Скопировать `server/*.mjs`, `src/lib/catalog-schema.mjs`, `src/data/properties.json`;
Astro, Chrome и node_modules серверу не нужны. Отдельно создать `.env` и DATA_DIR,
владелец — пользователь сервиса, права 600/700. Запускать Node через systemd или pm2,
с автоматическим перезапуском и writable DATA_DIR. Например:

```sh
cd /opt/monopoly
node --env-file=.env server/lead-proxy.mjs
```

nginx: [nginx.conf.example](nginx.conf.example) обслуживает статику и направляет
`/api/*`, `/media/*`, `/lead` на `127.0.0.1:8787`; Node не открыт извне. В environment
задать единый origin, например `ADMIN_API_ORIGIN=https://example.ru` и
`ALLOWED_ORIGINS=https://example.ru`. При статической сборке на этом домене публичные
`PUBLIC_*` переменные не нужны; если API вынесен на другой origin, задайте их явно.

Один HTTPS origin сохраняет cookie SameSite=Strict и исключает CORS в браузере.
CORS остаётся нужным только при отдельном origin API. Для `/admin/` добавьте в nginx
`X-Robots-Tag`, если нужен HTTP-заголовок помимо уже существующих meta noindex/nofollow
и robots Disallow.

## Безопасность и заявки в Telegram

Сессия: HttpOnly, Secure (исключение только 127.0.0.1), SameSite=Strict, 8 часов,
в памяти; выход/перезапуск гасят её. Точные Origin/Host, CSRF на операции,
bootstrap с custom header, лимит входа 5/мин/IP (через доверенный loopback-прокси).

POST `/lead`, GET `/health` остаются прежними. Проверка Origin общая с админкой; lead-sources не изменён.
Сервер валидирует поля, ограничивает тело 10 КБ и частоту 15/10 мин/IP, экранирует
HTML. Реальные отправки требуют личного чата после /start. Telegram: таймаут 6 с,
повторы при сетевых/5xx/429; при потерянном ответе возможен дубликат заявки.
Для доставки заявок серверу нужен доступ к Telegram: на VPS за границей прокси не нужен,
локально в РФ используйте прокси/VPN. Для HTTP-прокси запускайте
`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:PORT node --env-file=.env server/lead-proxy.mjs`
(замените `PORT` портом своего прокси); для `npm run dev:all` задайте те же переменные.
Не журналировать тела запросов, cookie и Telegram URL. `LEAD_DRY_RUN` не включать
в production. Подробнее контракт — [VERIFICATION.md](VERIFICATION.md).

Проверки: `node --test scripts/proxy-origin-test.mjs scripts/catalog-admin-test.mjs`; с браузером —
`ADMIN_BROWSER_TEST=1 node --test scripts/proxy-origin-test.mjs scripts/catalog-admin-test.mjs` (sandbox порт 8788).
Тесты используют фиктивные значения и мок Telegram; реальные настройки не читают.

Реальный HTTPS-туннель и Chrome: `node scripts/share-origin-browser-test.mjs`.
Запускать отдельно вне ограниченной песочницы, с доступом к Chrome/puppeteer-core, loopback и SSH к localhost.run, при свободных портах 8788/8791; `Sandbox API exited` означает остановку тестового API до запуска Chrome.
Занимает только свободные 8788/8791, использует sandbox DATA_DIR, фиктивный аккаунт
и LEAD_DRY_RUN=1; проверяет вход с Origin туннеля, cookie, добавление/удаление
карточки и заявку через UI. Свои процессы и временные данные удаляет при завершении.

TASK-074, отдельный поддомен Serveo + обрыв SSH + Chrome: `node scripts/share-serveo-browser-test.mjs`.
Запускать отдельно вне ограниченной песочницы, с доступом к Chrome/puppeteer-core, loopback, `ps` и SSH к Serveo с зарегистрированным `~/.ssh/serveo_ed25519`, при свободных портах 8788/8791.
Использует те же sandbox-порты 8788/8791, выделенный ключ только через ssh -i;
не запускайте одновременно с другими тестами, использующими 8788.

### Редактируемые тексты сайта (TASK-081)

Исходные значения и стабильные ID находятся в `src/data/site-texts.mjs`.
Одинаковые общие подписи используют одну запись: правка действует во всех
привязанных местах. Четыре текста с намеренными переносами сохраняют число строк.
`src/middleware.ts` при статической сборке добавляет к существующим элементам
`data-content-id`, индексы прямых текстовых узлов и частей строк. Новые элементы
не создаются; вложенные иконки, выделения, ссылки и `<br>` сохраняются.
При добавлении текста в исходники ID следует назначать вручную и не переименовывать
существующие. Скрипт `src/scripts/content-refresh.ts` получает только правки и
меняет `textContent` соответствующих узлов. Ошибка API оставляет исходный HTML.

- `GET /api/admin/content`: `{revision, overrides, items}`; сессия и CSRF, как у каталога.
- `PUT /api/admin/content`: `{baseRevision, changes: {"id": "Новый текст", "other.id": null}}`.
  `null` сбрасывает запись. Сохраняются только отличия в `DATA_DIR/content.json`.
  Конфликт версии возвращает 409, неизвестные ID/HTML/пустой или слишком длинный
  текст — 422, превышение общего размера 256 КиБ — 413.
- `GET /api/content`: публичные `{ok, revision, overrides}`, ETag с обязательной
  перепроверкой при следующем открытии страницы.
- Расписание редактируется в прежних полях `site-footer.text.8` и
  `site-footer.text.9`: например, `Пн-Пт с 09:00 до 18:00` или `Сб — выходной`.
  Статус офиса и JSON-LD используют те же строки; некорректные дни и часы
  отклоняются при сохранении с кодом 422.
- Типографика выполняется только при сохранении, существующим
  `scripts/typograf/rules.cjs`. При размещении API нужны также
  `src/data/site-texts.mjs`, `src/data/people.mjs` и `src/lib/office-hours.mjs`.
- По умолчанию запрос идёт на `/api/content`. При внешнем
  `PUBLIC_CATALOG_ENDPOINT` используется `/api/content` на том же origin.
  Отдельный адрес можно задать через `PUBLIC_CONTENT_ENDPOINT`.

Проверки: `npm test`, `npm run test:content`.
Браузерная проверка с одноразовым API и тестовым аккаунтом:
`CONTENT_TEST_SITE=http://127.0.0.1:4321 npm run test:content:browser`.
Настоящие данные входа для неё не нужны. Ручные тесты публичных туннелей
запускаются напрямую; автообнаружение `node --test` их пропускает.

Размеры исходных страниц сохраняются. Произвольно длинная правка может изменить
переносы строк и размеры блока: замена только текста сама по себе не гарантирует
нулевой CLS для любого нового содержания. Текст не обрезается и размер шрифта
автоматически не уменьшается; ограничения длины видны в редакторе.

### Превью редактора текстов (TASK-082)

В админке поля распределяются по фактическим `data-content-id` и порядку блоков
в HTML `/`, `/sell/`, `/buy/`. Повторяющийся ID остаётся общей записью и может
показываться на нескольких страницах; счётчики учитывают это. «Общие» содержит
шапку, подвал, модальную форму и подписи вне основного содержимого.

Превью — iframe настоящей страницы с того же origin. Родительский модуль
`src/scripts/admin/content-preview.ts` подставляет сохранённые значения и черновик,
добавляет подсветку и перехватывает клики только внутри этого фрейма. Он не
импортируется публичными страницами. Поздний ответ публичного API не затирает
черновик. Сохранение и серверная типографика остались прежними. «Отменить все»
отменяет несохранённые правки, «Вернуть исходный» готовит сброс записи к умолчанию;
сброс публикуется общей кнопкой «Сохранить».

CSP админки разрешает `frame-src 'self'`, не внешние origin. HTTP-заголовки
`Content-Security-Policy: frame-ancestors 'self'` и `X-Frame-Options: SAMEORIGIN`
заданы в Astro middleware для dev, share-сервере и шаблоне nginx. Директива
`frame-ancestors` не работает в meta-теге, поэтому статический хостинг должен
применять эти HTTP-заголовки сам. GitHub Pages не предоставляет настройку этих
заголовков; без поддерживающего их HTTP-сервера защита от чужого фрейма не
гарантируется. Конфигурация работающего nginx автоматически не изменяется.

Проверка: `npm run build && npm run test:content:preview`. Она создаёт собственный
одноразовый сервер и аккаунт, проверяет три ширины фрейма на пяти ширинах админки,
черновик, связь поля/превью, поиск, фильтр, сохранение, сброс и запрет чужого origin.
Реальные данные входа и действующие API-серверы в ней не используются.
