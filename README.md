# Монополия

Astro 7, TypeScript, обычный CSS. Статический сайт остаётся на GitHub Pages.
Node на VPS обслуживает заявки в Telegram и каталог недвижимости; новых зависимостей нет.

## Запуск

```sh
npm run dev
```

Обычный `npm run dev` запускает сайт и API админки вместе, читая существующий `.env`.
Точный адрес сайта и `/admin/` печатается в терминале. Если 4321 занят другим
проектом, выбирается следующий свободный порт; API разрешает вход с этого адреса.
Своя отправная точка: `npm run dev -- --port 4328`.
`Ctrl+C` останавливает оба сервера. `npm run dev:all` — тот же совместный запуск.
Любой `astro dev` (включая `npm run dev:site` и превью из IDE) сам поднимает
API на свободном порту 8787/8788, если тот ещё не запущен; API останавливается
вместе с Astro.
Занятые API-порты не освобождаются автоматически; настройка `ADMIN_API_PORT`
позволяет выбрать 8787 или 8788. Логин и хеш пароля берутся из `.env`,
данные каталога — из `DATA_DIR` или существующей `.local-admin/`.

> Продакшен: на VPS статика и Node работают за одним nginx-доменом. nginx направляет
> `/api/*`, `/lead` и `/media/*` в Node, а остальные пути отдаёт как статику;
> пример — [server/nginx.conf.example](server/nginx.conf.example).

## Показать сайт людям из другого города (npm run share)

В отдельном терминале, оставив API на 8787 запущенным:

```sh
npm run share
```

Команда собирает production-сайт с относительными `/lead`, `/api/catalog`,
`/api/admin/*` и `/media/` в отдельный `.share/session-*/dist`, не затрагивая
обычный `dist`.
Node раздаёт только эту сборку на `127.0.0.1:8790`; системный SSH открывает
публичную HTTPS-ссылку. Без настроек режим `auto`: localhost.run, при неудаче
за 20 секунд — serveo.net. Локальный `.share.env` выбирает Serveo для заказчика.
Скопируйте напечатанную «ПУБЛИЧНУЮ ССЫЛКУ»; рядом отдельной строкой выводится адрес
админки. Новые зависимости не нужны; закреплённый поддомен требует регистрации ключа.

Для заявок и актуального каталога нужен локальный API: `npm run dev` либо
`node --env-file=.env server/lead-proxy.mjs`. Без API сайт сообщает о недоступности каталога,
а отправка заявки показывает ошибку. Не запускайте второй API на занятом порту.
Изменения страниц видны после перезапуска `share`; каталог обновляется через API.

`Ctrl+C` останавливает только сервер share и его SSH-туннель, удаляет временную
сборку. `npm run share -- --keep` сохраняет её, точный путь печатается при остановке.
Другой порт: `SHARE_PORT=8791 npm run share`. Занятые порты команда не освобождает.

Без закреплённого поддомена адрес временный и меняется при перезапуске. Ссылка
работает только пока запущена команда
и компьютер подключён к сети. Туннель — сторонний посредник, через который проходит
трафик, включая данные заявок. **Ссылка не приватная:** любой, у кого она есть,
может смотреть сайт и отправлять заявки. Доступность из РФ не гарантирована;
если оба SSH-сервиса недоступны, варианты — ngrok (требует регистрации, по решению
заказчика) или SSH на свой VPS. Для постоянного показа на VPS используйте nginx
из [server/README.md](server/README.md#vps-и-https).

Безопасность: Astro/Vite не выставляется в интернет. `/admin/` и все методы
`/api/admin/*` доступны по публичной ссылке; остальные API-маршруты, кроме POST
`/lead`, GET `/api/catalog` и GET фото `/media/*.webp`, возвращают 404. Админка
доступна всем, у кого есть ссылка: защита — логин/пароль и лимит попыток входа.
Показ зависит от локального компьютера. Для постоянной работы используйте свой VPS и nginx. Передали
ссылку третьим лицам — после показа смените пароль: `node server/admin-set-password.mjs`.
Файлы вне сборки, скрытые файлы, исходные карты и обходы пути недоступны; листинга
каталогов нет. Cookie и `Set-Cookie` админки передаются только для `/api/admin/*`;
share передаёт исходный Origin и публичные `X-Forwarded-Host` / `X-Forwarded-Proto`.
Для входа и заявок включите `TRUST_PROXY=1` у API: помимо белого списка он принимает
Origin, точно совпадающий с переданными схемой и хостом, только от loopback-сокета.
HTTPS-cookie остаётся Secure и SameSite=Strict. `X-Forwarded-For` нужен для лимита входа.
**Включайте TRUST_PROXY только когда API слушает loopback за доверенным прокси**, который
проверяет и перезаписывает forwarded-заголовки. Настройки `.env` не печатаются.
Не публикуйте конфиденциальные материалы.

### Serveo: бесплатная стабильная ссылка

Один раз войдите в [console.serveo.net](https://console.serveo.net/) через Google/GitHub
и добавьте **публичную** часть отдельного ключа `~/.ssh/serveo_ed25519.pub`.
У заказчика ключ уже зарегистрирован. Приватный ключ остаётся на Mac, используется
только SSH и только для туннеля; не копируйте его в проект и не используйте для серверов.
Правила поддоменов и предупреждения: [документация Serveo](https://serveo.net/docs/).

Оставив локальный API с `TRUST_PROXY=1` на 8787, запустите:

```sh
npm run share -- --tunnel=serveo --subdomain=monopolia --key=~/.ssh/serveo_ed25519
```

Сайт: `https://monopolia.serveousercontent.com`, админка: тот же адрес + `/admin/`.
Не запускайте эту команду параллельно с уже работающим туннелем `monopolia`:
при переходе сначала завершите прежнюю команду её Ctrl+C.

Для запуска просто `npm run share` скопируйте `.share.env.example` в `.share.env`:

```dotenv
SHARE_TUNNEL=serveo
SHARE_SUBDOMAIN=monopolia
SHARE_SSH_KEY=~/.ssh/serveo_ed25519
```

Приоритет: флаг → переменная окружения → `.share.env` → `auto`.
Настройки туннеля не читаются из секретного `.env`; прежний `ADMIN_API_ORIGIN`
для API по-прежнему берётся оттуда, если не передан окружением.
`--tunnel=localhost.run` выбирает прежний сервис и игнорирует поддомен/ключ из
`.share.env`; переменные окружения и явные флаги поддомена/ключа предназначены для Serveo.
Пустой `SHARE_SUBDOMAIN` в режиме Serveo запрашивает случайный адрес.

На бесплатном тарифе при первом заходе может появиться предупреждение Serveo:
посетитель нажимает кнопку продолжения. Адрес стабилен, пока ключ держит поддомен;
это тестовый туннель без гарантии доступности, Mac должен быть включён и в сети.
`caffeinate -i` предотвращает автоматический сон на время команды, но не сон при
закрытии крышки. Без caffeinate выключите сон вручную. Бесплатный план ограничивает
число активных туннелей (сейчас 3); предупреждение включено.

Если поддомен занят или Serveo отклонил запрос, проверьте регистрацию `.pub` в Console,
затем выберите свободное имя через `--subdomain=другое-имя` (латиница) либо
`SHARE_SUBDOMAIN` в `.share.env`. Скрипт сверяет адрес с SSH и не подменяет его случайным.
Если используется явный `ALLOWED_ORIGINS`, обновите его под новое имя.
С `TRUST_PROXY=1` на loopback вход и заявки работают без ручного добавления Origin;
пример постоянного списка: `ALLOWED_ORIGINS=https://monopolia.serveousercontent.com,http://127.0.0.1:4321`.

При обрыве SSH или недоступности публичного адреса скрипт повторяет подключение с
паузами 5 → 10 → 20 → 40 → 60 секунд; после минуты работы пауза сбрасывается.
Проверка `/` каждые 30 секунд: любой HTTP-ответ, включая предупреждение, означает
«живо», DNS/таймаут и ответ `no tunnel` вызывают переподключение. Раздача сайта остаётся
работать. `Ctrl+C` завершает собственные SSH/caffeinate/сервер и удаляет временную сборку.


## Как добавить карточку

В `/admin/` войдите общим аккаунтом → «Добавить объект». Заполните заголовок,
адрес, цену и нужные дополнительные подписи. Выберите JPEG/PNG/WebP, проверьте
центральный кадр 4:3, нажмите «Сохранить». Карточка уже доступна в API; посетитель
увидит её при следующем открытии `/buy/`. Открытая вкладка проверяет каталог
каждые 30 секунд и при возвращении на неё.
В списке: изменить, скрыть/показать, удалить с подтверждением, выше/ниже.
Пересборка для карточек не нужна. Закрытая база остаётся иллюстрацией из макета.

## Доступ в админку

Вход только по логину и паролю. Смена пароля: `node server/admin-set-password.mjs`,
затем перезапуск Node. Команда сохраняет хэш пароля в `.env` с правами 600.
Telegram для входа в админку не используется.

Инструкции по окружению и HTTPS — [server/README.md](server/README.md).

## Заявки в Telegram

Формы используют существующий `src/scripts/lead-submit.ts` и POST `/lead`.
При сборке задаётся `PUBLIC_LEAD_ENDPOINT`; Telegram настраивается только на сервере.
Для доставки заявок серверу нужен доступ к Telegram: на VPS за границей прокси не нужен,
локально в РФ используйте прокси/VPN; для HTTP-прокси запускайте
`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:PORT npm run dev`
(замените `PORT` портом своего прокси).
Успех показывается после доставки. `LEAD_DRY_RUN=1` включает проверку без отправки.
Контракт: источник, раздел, страница, тема, контакт и способ связи; сервер
валидирует, ограничивает частоту и экранирует HTML. Подробности форм —
[отчёт TASK-044](design-reference/task-044-telegram-report.md).

## Проверки

```sh
npm run check
node scripts/catalog-check.mjs
node --test scripts/catalog-admin-test.mjs
ADMIN_BROWSER_TEST=1 node --test scripts/catalog-admin-test.mjs
node scripts/check-baseline.mjs
npm run build
```

Браузерный тест использует существующий Chrome/puppeteer-core, sandbox DATA_DIR
и порт 8788. Рабочий каталог, реальный аккаунт и Telegram не используются.
UI kit: `/ui-kit/`. Эталон 1440: `/` 17717, `/sell/` 16058, `/buy/` 16023.
В публичных страницах остаются демонстрационные условия из Figma; настоящие
предложения и материалы утверждает заказчик. Git, публикация и деплой выполняются отдельно.
