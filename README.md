# Монополия

Статический сайт агентства недвижимости: главная `/`, продажа `/sell/` и покупка `/buy/`. Цель — заявка через форму; приоритет — скорость загрузки. Все секции трёх страниц сверстаны и сверены с Figma на desktop 1440 px; результаты и оставшиеся визуальные погрешности — в `design-reference/qa-home.md`, `qa-sell.md`, `qa-buy.md`.

Стек: Astro 7, TypeScript, обычный CSS. Без React, Tailwind и новых клиентских библиотек. Ресурсы локальные: SVG, оптимизированные WebP, шрифты WOFF2. JavaScript обслуживает меню, карусели, FAQ, калькулятор и демонстрационные формы.

## Запуск и проверка

```sh
npm install
npm run dev
npm run check
npm run build
npm run preview
```

`dev` запускает сайт на `http://127.0.0.1:4321/`; `check` проверяет Astro/TypeScript; `build` создаёт статическую сборку в `dist/`; `preview` запускает её локально (точный адрес выводится в терминале). При параллельной работе использовать существующий dev-сервер и отдельный каталог сборки по `design-reference/tasks/_common.md`.

Библиотека компонентов: `/ui-kit/`, реестр: `/ui-kit/#registry`. Состав и параметры — в `UI_KIT.md`. Это служебная страница с `noindex`.

## Структура

- `src/pages/` — маршруты главной, продажи, покупки, UI kit и генерация robots/sitemap.
- `src/components/` — общие элементы и секции страниц.
- `src/layouts/` — общий `SiteLayout`: метаданные, шапка, footer и диалог заявки.
- `src/styles/` — токены, глобальный CSS, стили секций и UI kit.
- `src/data/` — реестр компонентов, вопросы FAQ, шаги сделки и таблицы сравнения.
- `src/lib/` — функции SEO и размеры динамических изображений.
- `public/assets/` — локальные изображения и декоративные ресурсы; `public/fonts/` — шрифты, `public/seo/` — OG-изображение.
- `design-reference/` — контексты Figma, планы, отчёты и проверки; `original-assets/` внутри — исходные растровые экспорты.
- `scripts/` — генерация SEO-ресурсов.

## Адаптив

Полный адаптив трёх страниц **ещё не завершён**. По `PROJECT_MEMORY.md` задача K адаптировала BuyMortgage, BuyClosedBase, BuyNewBuild и общие карту, шаги и сравнение для покупки/продажи. Пороги этих правил — `max-width: 1199px`, `767px` и при необходимости `539px`; desktop ≥1200 сохраняется. План главной — `design-reference/responsive-home-plan.md`; её `home-responsive.css` пока содержит только комментарий.

Последние проверки K/L/M фиксируют горизонтальную прокрутку узких страниц. Нужны завершение R1 (главная и общие шапка/footer/FAQ/формы), R2 (продажа и общие блоки внутренних страниц), затем сквозная QA на 1440, 1024, 768, 390 и 360 px. Сборка сама по себе не подтверждает мобильную готовность. Передача замечаний: `design-reference/K_REPORT.md` и `M_R1_R2_HANDOFF.md`.

## Неподключённые системы и заглушки

- Формы проверяют поля и согласие, но на страницах нет реального endpoint: заявки не отправляются и не сохраняются. `LeadForm`/`LeadSection` поддерживают `endpoint` и POST JSON; серверный обработчик и уведомления не реализованы.
- Sanity Studio, админка каталога и интеграция каталога не подключены. Карточки используют локальные данные из макета; корзины и оплаты нет.
- Нет реальных видео отзывов и кейса, PDF-презентации и PDF-анализа; кнопки воспроизведения/презентации сообщают об отсутствии материалов, PDF-анализ — иллюстрация.
- Юридические документы отсутствуют: кнопки footer показывают сообщение, подчёркнутые названия в согласии не ведут на документы.
- Адреса соцсетей, мессенджеров и Telegram-каналов не подключены. Телефон и почта в контактах уже имеют `tel:`/`mailto:`.
- Доступность «4 мест», срок акции «13 дней»/«до конца сентября», расчёт ипотечного платежа и банковские уведомления — статические данные или демонстрации из макета. Реальные условия/доступность не подключены.
- Домен в `astro.config.mjs` (`site`) не задан: canonical, абсолютный `og:url` и sitemap пока не генерируются. После задания `site` включатся автоматически; UI kit исключён из sitemap.

## Что нужно для запуска

Заказчику нужно подтвердить домен и размещение; предоставить endpoint формы с обработкой, хранением и выбранным каналом уведомлений; ссылки соцсетей/мессенджеров/каналов, видео и PDF; утверждённые юридические документы и условия согласия. Для реального каталога нужны данные объектов и настройка Sanity. Также требуется подтвердить контакты, часы работы, обещания и актуальные условия акций/ипотеки.

До запуска необходимо завершить адаптив и сквозную проверку. Пуш и публикация — только с отдельного разрешения пользователя.

Рабочий контекст — `agent.md`, распределение задач — `FOREMAN_PLAN.md`, история решений — `PROJECT_MEMORY.md`. Список ресурсов без ссылок из `src` — `design-reference/unused-assets.md`; ничего не удалено.
