# Монополия

Astro 7, TypeScript, обычный CSS. Статический сайт остаётся на GitHub Pages.
Node на VPS обслуживает заявки в Telegram и каталог недвижимости; новых зависимостей нет.

## Запуск

```sh
npm run dev:all
```

Откройте http://127.0.0.1:4321/ или http://127.0.0.1:4321/admin/.
Команда запускает сайт и API в одном терминале; `Ctrl+C` останавливает оба.

> Продакшен: на VPS статика и Node работают за одним nginx-доменом. nginx направляет
> `/api/*`, `/lead` и `/media/*` в Node, а остальные пути отдаёт как статику;
> пример — [server/nginx.conf.example](server/nginx.conf.example).

## Как добавить карточку

В `/admin/` войдите общим аккаунтом → «Добавить объект». Заполните заголовок,
адрес, цену и нужные дополнительные подписи. Выберите JPEG/PNG/WebP, проверьте
центральный кадр 4:3, нажмите «Сохранить». Карточка уже доступна в API; посетитель
увидит её при следующем открытии `/buy/` и прокрутке к карусели (кэш до 60 секунд).
В списке: изменить, скрыть/показать, удалить с подтверждением, выше/ниже.
Пересборка для карточек не нужна. Закрытая база остаётся иллюстрацией из макета.

## Получение пароля

«Получить пароль» в `/admin/` → открыть бота в своём личном аккаунте Telegram →
запрос доступа → одобрение владельцем → логин и пароль приходят **запросившему**.
Владелец (`ADMIN_TELEGRAM_ID`, по умолчанию личный `TELEGRAM_CHAT_ID`) получает
«Имя (@username) запрашивает доступ…» (без числового Telegram ID) и кнопки «Да, выдать» /
«Нет, отклонить». После решения исходные сообщения запроса у владельца и ожидающего
пользователя удаляются; затем приходит короткое уведомление о выдаче, отказе или истечении.
Для самого владельца действует тот же поток с одобрением.
Ссылка одноразовая, действует 10 минут с создания на сайте и привязывается к первому
открывшему её аккаунту. Одновременно доступны не более 3 запросов, не более 3/час/IP.
При отказе или истечении бот уведомляет запросившего; при повторном открытии сообщает,
что запрос уже отправлен. Незавершённый запрос сохраняется при перезапуске.
Сообщение с логином и паролем удаляется через 60 секунд; после успешного удаления бот
подсказывает запросить пароль на сайте заново. Временные ошибки удаления повторяются,
отложенные удаления и ожидающие запросы восстанавливаются после перезапуска.

Риск: `ADMIN_PASSWORD` хранится в `.env` открытым текстом. Получивший пароль получает
полный доступ к админке общим аккаунтом. Если сотрудник уходит, смените пароль:
`node server/admin-set-password.mjs`, затем перезапустите Node. Команда обновляет
открытый пароль и хэш; `.env` должен быть доступен только владельцу сервиса.
Если `ADMIN_PASSWORD` отсутствует, бот не выдаёт пароль и сообщает обоим о смене на сервере.
Отключение бота: `ADMIN_RECOVERY_BOT=0` и перезапуск Node.

Инструкции по окружению и HTTPS — [server/README.md](server/README.md).

## Заявки в Telegram

Формы используют существующий `src/scripts/lead-submit.ts` и POST `/lead`.
При сборке задаётся `PUBLIC_LEAD_ENDPOINT`; Telegram настраивается только на сервере.
Успех показывается после доставки. `LEAD_DRY_RUN=1` включает проверку без отправки.
Контракт: источник, раздел, страница, тема, контакт и способ связи; сервер
валидирует, ограничивает частоту и экранирует HTML. Подробности форм —
[отчёт TASK-044](design-reference/task-044-telegram-report.md).

## Проверки

```sh
npm run check
node scripts/catalog-check.mjs
node --test scripts/catalog-admin-test.mjs scripts/admin-recovery-test.mjs
ADMIN_BROWSER_TEST=1 node --test scripts/catalog-admin-test.mjs scripts/admin-recovery-test.mjs
node scripts/check-baseline.mjs
npm run build
```

Браузерный тест использует существующий Chrome/puppeteer-core, sandbox DATA_DIR
и порт 8788. Рабочий каталог, реальный аккаунт и Telegram не используются.
UI kit: `/ui-kit/`. Эталон 1440: `/` 17717, `/sell/` 16058, `/buy/` 16023.
В публичных страницах остаются демонстрационные условия из Figma; настоящие
предложения и материалы утверждает заказчик. Git, публикация и деплой выполняются отдельно.
